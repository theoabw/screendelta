# Convergence report, 2026-09-27

The workflow this repository commits to ends with `/speckit.converge`, which compares the specification with the
built system and produces a gap list. The command is read-only by design, so this file is where its output goes,
alongside the analyze report. Where analyze compares artifacts with each other, this compares the specification
with what was built: every acceptance scenario, every requirement, every exclusion and every edge case the
specification names, each with what satisfies it or what the gap is.

## Requirements

Thirty-three requirements: sixteen functional, eleven non-functional and six success criteria. Twenty-nine are
verified with a committed test and recorded output. The four that are not, and what each needs:

| Requirement | State | What it needs |
|---|---|---|
| NFR-004 (determinism) | in progress | Byte-identical output is demonstrated across two toolchains, two userlands, two thread counts and two collector settings. A second physical host is untested; this workstation has no architecture emulation registered and the owner's other machines were unreachable |
| NFR-007 (usability) | planned | A person who is not the author following the README while being timed. The script is `docs/vv/acceptance.md` and every command in it has been run by the author |
| NFR-008 (portability) | planned | Three targets build and the suite passes on two Linux userlands. The Windows runtime half needs a Windows machine |
| SC-005 (a person unfamiliar with the project) | planned | The same acceptance run as NFR-007 |

NFR-008 was recorded as planned while it had evidence behind it, which the pass corrected to in progress; the
matrix now shows the same state the evidence does.

## Edge cases

The specification names ten. Four had no test and two had no implementation, which is what this pass is for:

| Edge case | Disposition |
|---|---|
| Identical frames, and frames differing only by capture noise | Tested, on generated pairs and in the corpus noise case |
| Whole-screen change produces a bounded region set | **Gap closed.** The property had no test: the tile grid was removed for it, and the removal was pinned only by the accuracy corpus. `TestAWholeScreenChangeIsOneBoundedRegion` asserts one region covering the frame rather than a region per tile |
| A window dragged across the screen | Tested through the movement rules |
| A changed display scale or DPI reported as a condition | Tested: the viewport comparison includes the scale factor, and the condition is emitted and asserted |
| A moving cursor or blinking caret ignorable by configuration | Covered by the configuration rules: a region of interest excludes it, as the pipeline demonstration does with the clock in its status bar |
| A modal overlay while underlying regions are tracked | Tested: the cover and occlusion rules |
| Partial occlusion of a tracked region | Tested: the partial-change and occlusion cases |
| Frames arriving out of order | **Gap recorded, not closed.** The contract lists `out-of-order-timestamp` and this engine never emits it. A frame carries a sequence and no timestamp, by design, because a document with a timing field in it could not be byte-identical. A frame whose sequence does not advance is refused with the sequence in the error, which `TestPushRefusesANonMonotonicSequence` now pins. The condition stays in the enum for a capture layer that has timestamps of its own; this engine cannot produce one, and the contract now says so |
| Very large frames refused explicitly | **Gap recorded.** Nothing refuses a frame on size: the engine buffers two frames and would allocate until it failed. The memory requirement is about a long stream rather than about one frame, and a size guard is a configuration surface the specification does not currently ask for. Recorded here rather than fixed, because adding a limit is a requirement change rather than a convergence step |
| An empty stream, and a stream of exactly one frame | **Gap closed.** `TestAnEmptyStreamAndASingleFrame` covers both |

## Exclusions

The specification excludes text recognition and action planning, and the engine honours both: there is no OCR, no
classifier and no planner in the module, and the second consumer reads the document contract rather than adding
behaviour. The forbiddances that are testable are tested: no network import, no process execution, and no write
outside the declared output path.

Fifty-three of fifty-four tasks are complete. The one that is not is T051, which says to write the acceptance
