# Analyze report, 2026-09-26

The canonical `/speckit.analyze` command is read-only by design: it reports inconsistencies between the
specification, the plan, the tasks and the contracts, and writes nothing. This file captures what it
reported on this repository, because the report is evidence of the process.

## What it was run against

`specs/001-frame-delta-engine/` in its state after the plan and the contracts were written and before the
tasks were generated, and again after the tasks existed. The check that runs in CI and in `make check` is
the durable form of the same idea: `scripts/check_traceability.py`, which fails when a requirement has no
row in the matrix, when a row names a task that does not exist, when a row claims `verified` without a
test file and an evidence file, and when the matrix and the specification disagree about how many
requirements exist.

## Findings, and what happened to each

| # | Finding | Class | Resolution |
|---|---|---|---|
| 1 | NFR-004 (byte-identical output) had no task and no test named for it | coverage gap | The task list gained the determinism task, and the test that encodes two runs and compares bytes exists as `TestCompareIsDeterministic`, with the thread-count half still open |
| 2 | SC-005 (a new user produces a delta within two minutes) had no measurement method | unmeasurable criterion | The method is now the acceptance script in `docs/vv/acceptance.md`, which is written and not yet run; the criterion stays unverified rather than being quietly dropped |
| 3 | FR-014 (schema version in every document) was traced to a task that named the wrong package | traceability error | Corrected in the matrix; the version is emitted by the document encoder and rejected at decode time |
| 4 | Two requirements were phrased as implementation ("the engine MUST use a tile grid") | requirement written as design | Rewritten as behaviour ("the engine MUST report changed regions with bounds"), which allowed the tile grid to be removed later for a measured reason without changing a requirement |
| 5 | The data model described an identity's `confidence` without saying what it is derived from | underspecified | Now stated: the match score for a carried-over identity, one where there is no competing interpretation, and the appearance margin for a reacquisition |

## What the analyzer cannot see, and what covers it

It reads artifacts, so it cannot see whether a test asserts the thing the requirement says. Two defects
of that kind were found by other means and are recorded in `docs/vv/results.md`: a document validation
rule that permitted schema-invalid output (found by an independent review reading the schema next to the
validator), and a measurement suite that passed while checking nothing (found by a review that tried to
pass it with a deliberately wrong engine). Both are reasons the report treats review and mutation as
verification activities rather than as optional extras.
