# User acceptance script

Executed by a member who did not implement the feature, against the acceptance
scenarios in `specs/001-<slug>/spec.md`. The outcome of each scenario is recorded
here, because section 5.1 of the report is graded on validation against the
stakeholders' needs and not only on tests passing.

## Preparation

1. Build or start the system following `specs/001-<slug>/quickstart.md`.
2. Prepare the data the scenarios need.
3. State the environment: operating system, browser or client, and versions.

## Scenario checklist

| Scenario | Requirement | Steps | Expected | Observed | Verdict | Tester | Date |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

Verdict values: `accepted`, `accepted with comments`, `rejected`.

## Comments from the tester

Free-form notes on usability, missing behaviour and anything the specification
did not anticipate. A rejected scenario produces either a defect in
`docs/vv/results.md` or a change to `spec.md`, and the choice is recorded here.
