Classification is asserted, not only localisation: changed-label expects changed,
moving-button expects changed on the first comparison (no baseline yet) and moved
after that, occluded-button expects changed. Every matched region carried the expected
class. The sweep asserts localisation only, and the reason is recorded in the test:
whether a uniformly different area is a changed element or a removed one cannot be
decided from pixels, so asserting classes there would assert the implementation's guess.

Why this is the second revision. The first measurement scored 27 pairs and 9 expected
regions, and an independent review showed it could pass with broken classification and
with false removals on transitions it never scored. What changed:

1. Ground truth is now computed from the rendered pixels by an oracle in
   internal/corpus, instead of being stated by the generator. The old definition
   recorded the element that moved, which demanded regions for frame pairs where the
   translation had moved the element clear of its old position, missed overlays clipped
   at the frame edge, and asked for one box where the pixels changed in two places.
2. Every adjacent pair is scored, not a selected subset. A mutant that emitted spurious
   removals on unselected transitions previously passed.
3. 5,001 frames of the sweep case give the 5,000 pairs SC-001 asks for, with answer keys
   derived from the pixels.
4. Classification is checked against the case's own statement of what happened, so an
   engine that calls every change "changed" no longer scores 1.0000.
5. The oracle knows the configured noise floor. Counting sub-floor differences as
   changes scored the engine against material the requirement says it must ignore.
6. The noise case generates noise at half the floor per frame, so two noisy frames cannot
   differ by more than the floor. The previous material could produce a 72 pixel blob six
   levels above the floor, which is a change by the specification's own definition and
   cannot be scored as a false positive.

Defects the revised measurement found, all fixed in the diff package:

  AUD-004  The tile gate cut genuine changes. A sixteen pixel tile grid decided what a
           change was by the tile mean, so a change that reached into a tile whose mean
           stayed under the floor was cut at the boundary and reported as two overlapping
           regions. Sweep precision was 0.9995 with 13 such duplicates. The tile grid is
           gone: changed pixels are found per pixel and grouped by connectivity, which
           removed all thirteen and is a smaller implementation.
  AUD-005  Remembered geometry was rewritten from the current frame's changed areas, so a
           frame pair that changed nothing erased the baseline and the next change was
           reported as added rather than changed. Elements whose pixels did not change now
           carry over.
  AUD-006  Two elements a tile apart were merged into one region. Grouping by tile
           adjacency reported one region where a consumer expects two; sweep recall was
           0.9947. Grouping by pixel connectivity reports both.
