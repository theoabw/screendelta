Element identity measurement, 2026-09-26, second revision.
Commands: go test ./internal/identity/... -v, and the identity tests in internal/diff and internal/stream.

What is demonstrated, and where:

1. An identity is stable while an element is tracked.
   internal/identity:  TestAMovingElementKeepsOneIdentity, TestTheSameSequenceProducesTheSameIdentities
   internal/diff:      TestATrackedElementKeepsOneIdentityAcrossFrames, TestContinuityOfAnIdentity
2. An identifier is never reused within a session.
   internal/identity:  TestIdentifiersAreNeverReused (a thousand frames of four frame cycles: every
                       identity issued once, every retirement recorded, no retired identity handed out
                       again), TestRetireAllEndsEveryElementWithoutReissuingNumbers,
                       TestSetRulesChangesTheWindowWithoutLosingIdentities
   internal/stream:    TestTheDifferIsToldAboutAViewportChange, TestAViewportRoundTripStillResets
3. The identity table does not grow with the length of the session.
   internal/identity:  TestRetiredEntriesAreBoundedByTheRetentionWindow (75 entries after 200 cycles
                       and 75 after 400), TestMemoryDoesNotGrowWithStreamLength
   internal/stream:    TestMemoryCeiling (10,000 frames, heap identical at frame 1,000 and 10,000)
4. The uncertainty marker exists and is set when an identity is reacquired after retirement.
   internal/identity:  TestReappearanceAfterOcclusionIsNewAndUncertain
   The marker is set by the identity package. See the limitation below for why the engine's classifier
   does not reach that path in the scenarios tested.

Requirements:
  FR-006  identifiers stable across a stream and never reused within a session
          The allocation counter is demonstrated monotonic and never reused. Stability of the handle

  NFR-009 at least 80 percent line coverage on the geometry and identity modules

Why this is the second revision, and what the first one got wrong.

An independent review falsified six claims, five of them reproduced with tests. What was fixed:

- A large element could take the identity of a small one inside it. Containment scored a perfect one
  and tied with an exact match, so the older identity won and the answer depended on allocation order.
  Matches are now ranked: an overlap match beats a containment match, and ties are broken by the
  smallest element and then by identifier, so the result is a property of the geometry rather than of
  history. Test: TestASmallElementInsideALargeOneKeepsItsOwnIdentity, run in both allocation orders.
- An element that sat still for longer than the occlusion window was retired as though it had been
  covered, so the next change to it was reported as a reacquisition of something new. An element ages
  only when the area it occupies changed and it was not matched: nothing changed where it is means it
  is still on the screen. Test: TestAnElementThatSitsStillIsNotRetired.
- Retired entries were kept forever, so the table grew with the session. They are now dropped once
  they are too old to be worth reacquiring, and the counter keeps rising, so dropping one can only
  turn a reacquisition into an addition. Tests: TestRetiredEntriesAreBoundedByTheRetentionWindow.
- A removal that could not name a live element allocated a new identity and left it live, so a
  consumer was told an element it had never seen was gone while the engine kept matching it. The
  fallback identity is retired at once. Test: TestVanishWithNothingToRetireAllocatesAName.
- A viewport change could leave identities live: the engine skipped the comparison, so the differ
  never learned, and a scale change or a size round trip was invisible to it. The interface now has
  Reset, the engine calls it on a viewport change, and the round trip is covered.
- The size gate had a discontinuity where a contained rectangle of three tenths the area lost its
  identity while one of 0.29 kept it. The containment path no longer applies a size ratio.

What is not fixed, and is therefore not claimed.

- The engine cannot tell a cover from a content change. When an element is covered by a larger one,
  the covering area is reported as a change of the covered element and inherits its identity, and when
  the cover leaves, the return is reported as a change of the cover. The uncertain marker exists for
  this case and the classifier does not reach it. Recorded in the test that asserts what the engine
  does say: TestAReplacementIsReportedAsRemovedAndAdded.
- An element whose pixels did not change cannot be reported as gone, so a disappearance and a
  content change look the same in a document. Distinguishing them needs appearance reasoning that
  this stage deliberately does not have.
- A partial change replaces the tracked footprint of an element, so successive changes in different
  parts of one large element can be given different identities.
- delta.Decode accepts a document missing the identity fields, because a missing JSON field becomes a
  valid zero value in Go. The engine always emits them; a library consumer reading a document from
  elsewhere is not protected.
