Memory measurement, 2026-09-26, second revision.
Commands: make memcheck, and the retention test in the same package.

stream retention, 10,000 frames at 1920x1080, comparison stubbed:
  wall clock         2.459 s
  peak heap          25,200,336 bytes  (24.0 MiB)
  peak resident      23,597,056 bytes  (22.5 MiB)
  engine buffers     16,588,800 bytes  (two 1920x1080 rgba8 buffers)
  heap at frame 1000   25,200,336 bytes
  heap at frame 10000  25,200,336 bytes

real pipeline retention, 10,000 frames at 320x240 through diff and fingerprint:
  wall clock         8.094 s
  regions reported   11,109
  heap at frame 1000   1,327,632 bytes
  heap at frame 10000  1,329,600 bytes
  peak resident      10,473,472 bytes  (10.0 MiB)

allocation steady state, 320x240, two consecutive windows of 1,000 frames:
  first window   8,220 bytes per frame
  second window  8,226 bytes per frame
  pixel buffers allocated by the engine: 2

Requirements this measures:
  NFR-003  at most 128 MB over 10,000 frames, no growth with stream length
           met: 24.0 MiB peak heap and 22.5 MiB peak resident against a 128 MiB ceiling,
           and the heap is identical at frame 1,000 and frame 10,000. The real pipeline
           holds 10.0 MiB resident after 10,000 frames.

Why this is the second revision. The first version sampled only the heap and allowed
eight megabytes of growth between frame 1,000 and frame 10,000. An independent review
retained 512 bytes per frame inside the engine and both tests still passed, with 4.6 MB
of growth absorbed by the allowance. The measurement now:

1. Reads resident memory from /proc/self/statm, because the requirement is stated in
   resident memory and a live heap object count is not that.
2. Allows one megabyte of growth over the nine thousand sampled frames. Half a kilobyte
   per frame accumulates to 4.6 MB and is caught. Verified by introducing exactly that
   leak and watching both tests fail with the growth named, then reverting it.
3. Measures the real differ and fingerprint over 10,000 frames as well, so retention is
   claimed for the pipeline that actually runs rather than only for a stub.

What this still does not measure: latency and throughput. Those are the diff package's
benchmarks, which do not exist yet, so NFR-001, NFR-002 and SC-002 remain unmeasured.
